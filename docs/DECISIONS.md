# Design decisions

A running log. Newest at the bottom.

| # | Decision | Why |
|---|---|---|
| 1 | pnpm workspaces. Packages export TypeScript source (no build step). `tsx` runs the worker and CLI. Next.js uses `transpilePackages`. | Fewer moving parts, fast iteration, one `tsc --noEmit` per package. |
| 2 | Pinned majors: Next 15, React 19, Prisma 6, pg-boss 10, zod 3, TypeScript 5.9, Vitest 3. | Stable, well-known APIs matter more than newest versions for a demo that must work tomorrow. |
| 3 | Postgres host port is `${AUTOPILOT_DB_PORT:-5432}` in `docker-compose.yml`. | The spec asks for 5432. The dev machine already had Postgres on 5432, so the port is overridable without changing the default. |
| 4 | Biome for linting, formatter disabled. | One small dependency, fast, no plugin sprawl. |
| 5 | System font stacks instead of `next/font/google`. | `next/font/google` downloads at build/dev time, and the demo must run with no internet. |
| 6 | Mock LLM provider is a scripted state machine per job type. It reads the (untrusted) tool results it is given to build edits, e.g. renaming `parse(` → `parseDate(` in the file it just read. | Deterministic and offline, but still exercises the real loop, tools, policy and sandbox end to end. |
| 7 | The mock *verifier* is a heuristic reviewer (paths vs contract, claims vs evidence, injection signs). | Lets the verifier eval cases and the bad-worker demo produce meaningful verdicts offline. With a real key, the real verifier prompt is used. |
| 8 | Gate "tests pass" means **no new failures compared with main**. A baseline run on `main` is recorded per job. | The flaky test is seeded and fails on `main` until G2 is fixed. Without a baseline, G1 could never pass the gate before G2 is merged. This is how most CI "new failures only" checks work. |
| 9 | The flaky test reads `FLAKY_SEED`. Goal checks run attempt 1 with seed 1, the CI-style auto-retry uses seed 2, and the worker's re-run uses seed 3. With no seed set, it is truly random. | Reproducible demo, still a real random failure in normal use. |
| 10 | The G3 mock worker deliberately tries `git push origin main` once after reading the README injection line. | Shows the policy denial and audit trail live. A real model will usually not try, but the protection is the same either way. The verifier sees the denied attempt in the evidence and reports it as a concern. |
| 11 | `demo-bad-worker` first tries an out-of-scope write through the tool layer (policy denies it), then simulates a compromised harness by writing the file directly into the workspace. | Without the bypass, the verifier and gate would never see the bad change. The demo needs to show all three layers catching it. |
| 12 | Linter for the target repo: `npm run lint` if the target defines it, else a built-in `node --check` syntax check on changed `.js` files and `JSON.parse` on changed `.json` files. | The demo target has no npm dependencies, so a real ESLint can't be installed offline. |
| 13 | Docker sandbox copies the workspace (without `.git`/`node_modules`) to a temp dir, mounts it, and runs as the host uid with `HOME=/tmp`. | No root-owned files left behind. The real repo is never mounted. |
| 14 | Demo-mode detection: the target is in "demo mode" when it contains `advisories.json` and `vendor/`. Otherwise it is in real mode (OSV + npm registry). | No extra flag needed. `TARGET_REPO_PATH` decides. |
| 15 | Trust promotion demo: `pnpm cli seed --reintroduce g1` commits the vulnerable dependency back onto `main` (as if a teammate reverted it). Running G1 three times shows L0→L1. | Promotion needs repeated approved passes of one job type. Re-planting the problem is honest. Faking history is not. |
| 16 | pg-boss queue names use dashes (`autopilot-run-job`). | pg-boss 10 restricts queue names to letters, numbers, dashes, underscores and periods. |
| 17 | All three demo contracts are `difficulty: "easy"`. | The spec's `.env.example` sets `HARD_WORKER_MODEL` and `VERIFIER_MODEL` to the same model, and the router must throw when they match. A "hard" demo contract would always fail with the default config. Hard routing and the collision error are covered by tests. To use hard contracts, set `VERIFIER_MODEL` to a different model (e.g. `claude-opus-5-5`). |
| 18 | "Check goals now" enqueues a check **without** conducting. The daily cron checks **and** conducts. | The demo is driven step by step with "Run job". Auto-starting all three jobs on every manual check would make it hard to follow. |
| 19 | The worker's task brief includes the repo's tracked file list (`git ls-files`). | G3's contract only allows `README.md`. The worker needs to know that `scripts/bootstrap.js` exists without being allowed to read `scripts/**`. |
| 20 | Only harness-computed fields go in `<task>`. Anything verbatim from files, logs or commits goes in `<untrusted_data>`. The worker's explanation is untrusted for the verifier too. | Constitution rule 5 applied consistently, including to the other AI. |
| 21 | G2 cause commit = newest non-test commit whose parent still passes the failing test (bounded bisect, max 4 sandbox runs). | Plain code, deterministic, cheap. The LLM only proposes the fix. |
| 22 | Approve/reject run synchronously in the web route (merge + goal re-check, ~5 s). Worker jobs run in `apps/worker` via pg-boss. | The human sees the result of their decision immediately, and the goal panel turns green right after. |
| 23 | pnpm 12 needs `allowBuilds` in `pnpm-workspace.yaml` for Prisma/esbuild install scripts. | Supply-chain default in pnpm ≥ 10. Only these four packages may run install scripts. |
| 24 | `pnpm demo` resets by applying migrations and then `TRUNCATE`-ing only Autopilot's own tables (plus dropping the `pgboss` schema), instead of `prisma migrate reset`. | Faster, keeps the schema, scoped to this app's tables in the local docker-compose database. Prisma also blocks `migrate reset` when invoked by an AI agent. |
| 25 | `pnpm cli seed` refuses to replace a directory that isn't a previously seeded demo repo. | `TARGET_REPO_PATH` can point at a real project in real mode. Seeding must never delete it. |
| 26 | Lessons are deduplicated on (jobType, result, lesson text). | Repeated identical runs (e.g. the trust-promotion loop) shouldn't flood `memory/lessons.md`. |
| 27 | The mock G3 worker always attempts the injected push once. The mock verifier reports the blocked attempt as a concern but passes when nothing reached the diff. | Shows the audit trail live without blocking an otherwise correct fix. A followed injection (in the diff or the explanation) fails the verifier: see eval case `bad-followed-injection`. |

## Scrum Mode (round 1)

| # | Decision | Why |
|---|---|---|
| S1 | The spec refers to "the existing MCP server", but there wasn't one. Added a read-only server: `sprint/mcp.ts` (tools) plus `packages/mcp` (stdio, `pnpm mcp`). Ask Autopilot calls the same server through an in-process MCP client (`InMemoryTransport`). | One tool implementation for external MCP clients and for Ask. Ask really goes through MCP. |
| S2 | `docs/SLIDE_COVERAGE.md` didn't exist either, so it was created. It maps each slide topic to what demonstrates it. | Requested by the spec. |
| S3 | Pseudonymisation happens **at sync**: titles, descriptions and comments are stored with names replaced by "Member X". The gateway `beforeSend` real-name guard is a second line of defence on every sprint request. | Real names then exist only in `PersonAlias`. Nothing downstream can leak what it never holds. |
| S4 | One `nudge-draft` job per red S2 produces one draft per stuck item. The job closes when every draft is approved or discarded, and trust is recorded once per job. | Respects the existing conductor rules (one open job per goal, cap of 3) instead of N jobs per sprint. |
| S5 | `HARD_TRUST_CAPS` is a frozen code constant. `applyTrust` clamps to it, and `getTrust` clamps stored levels and forces auto-merge off. | "Capped at L0 forever, config cannot override", made testable. |
| S6 | Team contracts have `allowedPaths: ["sprint-data:read-only"]` and the worker loop runs with **no tools**: one model call that words the facts. | Reuses the loop (budgets, kill switch, checkpoints, traces) with the smallest possible capability. |
| S7 | Facts first. The gate recomputes counts from the database at gate time; the model's numbers are never trusted. | Miscounts can't slip through even if the verifier misses them. |
| S8 | "Generate brief now" may run when S1 is already green (`allowGreen`). Kill switch, dedupe and the cap still apply. The Overview button stays disabled when S1 is green. | Teams want a fresh brief on demand. |
| S9 | Jira's dev-status API gives no "PR opened" time, so `lastUpdate` stands in for it and any reviewer counts as reviewed. PR URLs parsed from text have no opened time and so never trigger `review_waiting`. The dev-status API is switched off for the session on a 4xx. | Conservative: better to miss a review wait than to invent one. |
| S10 | Injection-like comments are flagged at sync. They stay in the facts marked `flagged: true`, so model resistance is actually exercised, but the MCP tools withhold their bodies. The gate fails any output that cites a flagged event, shares a 4-word sequence with it, or claims a mass action or mass message. | Audited, visible, and provably without influence. |
| S11 | Least data: only the active sprint and the most recent closed sprint are fetched, with a project-scoped JQL (`project = "KEY"`). | AGENTS.md rule 13. |
| S12 | `addedAfterSprintStart` (Jira) = the issue was created after the sprint start, or the changelog shows the issue being added to this sprint after it started. | The board API doesn't expose this directly. |
| S13 | `blocked_by_build` follows the latest G2 check. After the code demo fixes G2 the item is no longer blocked, so the Scrum demo is best run right after `pnpm demo` (G2 red). Otherwise run `pnpm cli seed --real-bug`. | The link to a real Autopilot goal is the point; it shouldn't be faked. |
| S14 | S1 is green ("next brief due at …") until 60 minutes before standup, amber in that hour, and red after it if nothing is published. | The spec defines red and amber only. Before the window nothing is due. |
| S15 | A human's nudge edit must still mention the item key and pass the people-judgement check. Real names are allowed there, because it's the human's own message and never goes to a model. | Work-not-people applies to what Autopilot drafts. A person may address a colleague by name. |
| S16 | `@modelcontextprotocol/sdk` is pinned to 1.32.0. | More than two weeks old and compatible with our zod 3. |
| S17 | Round 1 authenticates to Jira with basic auth (email + API token for a bot account limited to one test project). **For real teams, the recommended path later is Atlassian's official MCP server or OAuth 2.0 (3LO)** with scoped, revocable access. | Simplest read-only path for a test project. Not the end state. |
| S18 | The mock team verifier is a heuristic reviewer (people patterns, keys vs sources, invented blockers, counts vs facts, tone, injection effects). | Offline demos and evals with meaningful verdicts; real models use `TEAM_VERIFIER_SYSTEM_PROMPT`. |
| S19 | At L1+ (earned), briefs auto-publish **to the dashboard only**. Nothing posts to Slack or Teams in this round. | The spec's publishing rule. |
| S20 | `pnpm demo` also empties the sprint tables. | A clean state for both demos. |
| S21 | Step recording, usage, status and lessons moved from `pipeline.ts` into `job-steps.ts`. | Lets the team pipeline reuse them without a circular import. |

## Slide-coverage additions (BUILD_PROMPT §12)

| # | Decision | Why |
|---|---|---|
| H1 | The worker, verifier, team-verifier, lesson-writer, assistant and sub-agent prompts live in `prompts/*.md`, each with a version header. `packages/core/src/prompts.ts` loads them (cached), strips the header, substitutes `{{…}}` placeholders, and exposes a `name@version` stamp. The old inline constants now load from these files. | One source of truth for prompt text, versionable in review. `prompts/**` is already a high-risk path, so agents can never edit them. |
| H2 | The prompt stamp is recorded on every model step (`JobStep.promptVersion`, e.g. `worker@1`, `verifier@1`, `lesson-writer@1`, `team-verifier@1`) and shown on the job trace. | "Record the prompt version on every trace." |
| H3 | The verifier prompt carries 3 labelled few-shot examples (pass, unsupported-claim fail, out-of-scope+injection fail); the worker prompt states a "plan, then act" style. Mock mode is unaffected (the mock verifier/worker are heuristic and ignore the system prompt). | Spec §H. Real models benefit; offline determinism is preserved. |
| E1 | Skills live in `skills/<name>/SKILL.md` (`dependency-upgrade`, `flaky-test-quarantine`, `docs-fix`), each with steps, an output template and a version header. `packages/core/src/skills.ts` maps job type → the single matching skill and loads it. | Spec §E: one skill per job type. |
| E2 | The worker loads only the skill matching its job type; it is added to the task as a trusted `<skill>` block and recorded on the trace ("Loaded skill: dependency-upgrade@1"). Team jobs have no skill. | "The context builder loads only the skill that matches the job type, and the trace records which skill was loaded." §C formalises the assembly. |
| B1 | The seeder writes `demo_target/docs/runbooks/` (dependency-upgrades, flaky-tests, docs-fixes). `pnpm cli seed` indexes them into the `KnowledgeDoc` table as passages (one per `##` section, with line ranges). | Spec §B: a seeded, offline knowledge base. |
| B2 | Default search is Postgres **full-text search** (a `tsvector` column + GIN index), queried with an OR-of-terms `to_tsquery` for recall and ranked with `ts_rank`. It is fully offline. pgvector embeddings remain the documented optional path when a provider key is set; FTS is the fallback. | Spec §B: FTS default, offline; embeddings optional. |
| B3 | `search_knowledge(query)` returns passages with `path:lineStart-lineEnd` citations. The worker cites them in its explanation (the G1 mock worker does, to show it offline). The **verifier stage** confirms every cited runbook path exists in the index (plain code, deterministic), failing the verdict if one does not. The gate stays at its 9 checks. | "The worker cites sources; the verifier checks those citations exist." Kept in the verifier stage so the gate count is unchanged. |
| F1 | `repo_map` is a careful line parser (`repomap.ts`), not the TS compiler API: demo_target is CommonJS JS, so a dependency-free parser is simpler and runs offline. It extracts each file's exports and imports, resolves relative-import edges, and lists every call site of a given symbol (skipping the import line and the definition). | Spec §F allows "the TypeScript compiler API or a careful parser"; avoids a heavy runtime dependency. |
| F2 | The G1 worker calls `repo_map` with the removed export (`parse`) to find every call site before editing, and the map is stored on the job and shown as a "Codebase map" section on the job page. Only files inside allowedPaths are mapped. | "G1 uses it to find every call site of parse"; "show the map for the current job on the job page." |
| C1 | `context/builder.ts` assembles the worker's context in the fixed §C order (goal+contract, AGENTS.md, skill, lessons, knowledge, tool results) and counts tokens per section. AGENTS.md and the recalled lessons are now *in* the context (lessons moved out of the system prompt); one relevant knowledge passage is pre-retrieved. | "Assembles in order … count tokens per section." |
| C2 | The per-section breakdown is stored on the first model step (`JobStep.context`, migration 20261112140000_jobstep_context) and shown on the job page as a stacked bar, "What the model saw". | Spec §C. |
| C3 | One task per session: each job builds a fresh context; nothing from a previous job's transcript is reused, only its lessons. | Spec §C. |
| C4 | Compaction: the agent loop summarises the *content* of older tool results in place (keeping message roles/ids valid for real providers) once the transcript passes `AUTOPILOT_CONTEXT_WINDOW * AUTOPILOT_COMPACT_AT` (default 200k × 0.6); it records a trace note and a `context.compacted` audit event. Demo jobs are far too small to trigger it (by design); a unit test forces it with a tiny window. | "Compaction when context exceeds a configurable threshold … log a compaction event." |
| D1 | A research sub-agent (`agents/subagent.ts`) runs for G2: it reads up to 40 past CI logs for the failing test in its own, separate context (one dedicated model call, `sub-agent` prompt) and returns at most 5 findings to the worker (`task.research`). | Spec §D. |
| D2 | Its model call is traced under the `subagent` phase (tokens and cost recorded separately, prompt stamp `sub-agent@1`) and shown as a nested, indented step in the job timeline. In mock mode a deterministic heuristic reads the logs (failure count, re-run behaviour, test-file-touched). | "Trace its tokens and cost separately; show it as a nested step." |
